Why DroidCrate

The phone stays connected. The work stays in one place.

Most Android tasks are scattered across five programs, three websites and a folder of remembered command lines. DroidCrate reads the phone over USB and does the job with one verified toolchain.

Real device facts

Read the model, Android version, build, security patch, chipset and bootloader state before any action.

Apps without another tool

Install an APK by picking it or dropping it on the window, export a package, freeze, unfreeze, clear data or uninstall.

Files and full backup

Push and pull files or folders with progress, then back up DCIM, Pictures, Download, Documents, Movies, Music and WhatsApp.

Screen capture and live view

Take a PNG screenshot, record up to three minutes of MP4, or open a live view and tap the phone from the window.

Fastboot from your own disk

Flash a partition from a local image, erase, sideload an OTA ZIP, and lock or unlock the bootloader. Nothing is downloaded.

Guard rails, not hidden commands

No bypasses, no FRP tricks. Every high-risk action needs a second click, a checklist, and a visible command.

The workbench

Six tabs. One device picker.

The phone stays connected while you move between them. Everything runs on the bundled, verified Platform Tools.

01

Overview

Model, Android version, build, security patch, chipset and bootloader state. Restart to system, bootloader, recovery, fastbootd or power off.

02

Apps

List every package, install or export an APK, freeze or unfreeze, clear data and uninstall — through pm with safe arguments.

03

Files

Send any file to any phone path, pull a file or folder back, and run a full backup or restore of the usual phone folders.

04

Screen

Screenshot, up to three minutes of MP4, or a live view that refreshes about once per second with Back, Home, Recents and Power.

05

Flash

Pick a local boot, recovery or system image and flash it in fastboot, erase a partition, sideload an OTA ZIP, unlock or lock.

06

Terminal

Run any adb or fastboot command with presets, output, exit status and duration, plus a streaming logcat with a live filter.

Safety

Real tools. Explicit guard rails.

DroidCrate can flash, erase and unlock, so it says exactly what it will do and asks before it does it. It is a workbench for phones you own — never a bypass.

The line DroidCrate does not cross

It cannot remove a screen lock, bypass an account or FRP, or defeat ownership protection. There is no hidden command, plugin or build that adds this.

Flashing is deliberate. The Flash tab needs a fastboot device and a local image you chose, plus a confirmation before every write.

Erase and unlock are gated. Each one requires a second click, and the command is shown before it runs.

Commands are visible. The terminal shows the exact command, output, exit status and duration, and history keeps it.

Ownership gate. First launch asks you to confirm that you own the devices you connect. High-risk checklists ask again.

Nothing leaves the PC. No telemetry, no account, no cloud. The only calls are the one-time Platform Tools download and an optional update check.

Verified toolchain. Google's Platform Tools 37.0.1 is checked against a pinned SHA-256 before extraction, and adb runs only from that copy.

Slow down before risk

DroidCrate installs the verified Platform Tools once, then works offline. You choose every file from your own PC.

Questions

Straight answers.

Does DroidCrate bypass FRP or a screen lock?
No. It cannot remove a screen lock, bypass an account or FRP, or defeat ownership protection. There is no hidden command or build that adds this.
Is flashing safe?
Flashing is never risk-free. DroidCrate only flashes a local image you selected, shows the command, and asks for confirmation before every write. Read the checklist first and keep a backup.
Does it need internet?
Only for the one-time Platform Tools download and an optional content update. The workbench, lessons, checklists and history work offline.
Which phones are supported?
Any Android phone that exposes adb or fastboot over USB and that you own. Device detection reads Windows Plug and Play locally, so it works without adb for the first identification.
Does it send anything to a server?
No telemetry, no account, no cloud. Files you push, pull, export or flash go between your PC and your phone. Operation history stays on the PC.
Why is the installer unsigned?
There is no code-signing certificate yet, so SmartScreen may warn you. Check the SHA-256 on this page, or build from source.
